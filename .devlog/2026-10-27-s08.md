## Result

The user reports slow opening, zoom moving in bursts and details appearing slowly;
it felt fine the previous day. Reproduced the original wheel-completion failure on
D3 (Silchar network). Its payload contains 152,832 primitives, including about
1.5 million hatch segments. Individual raster tiles took 16–27 ms despite the
nominal 8 ms budget: canvas drawing defers substantial work until compositing.

Spatially partitioning disconnected hatch strokes reduces repeated offscreen path
work without dropping source strokes or changing the existing culling threshold.
D3 and D4 now pass the original wheel-completion checks at DPR 1. This is a partial
repair: DPR 2 still misses the original deadline, and a fresh-cache D4 opening still
takes about seven seconds, mostly conversion. Do not report the app fully restored.

## Changes and decisions

- `viewer/canvas.ts`: partition hatch strokes within their existing batches. Keep
  original batch ordering, selection/picking primitives and size thresholds. Join
  visible pieces before stroking. Existing s07 bounded grid traversal is preserved.
- Keep the displayed raster layer as a stand-in when images/fonts/scene state
  change during wheel motion; defer replacement tiles until the gesture settles.
  Explicitly clear both layers on a new drawing, preventing old-drawing stand-ins.
- `viewer/main.ts`: bound the initial animation-frame wait with a 50 ms timer;
  background/embedded tabs could otherwise stall before sending `/api/drawing`.
  Render the first canvas frame before dismissing loading and recording open time.
- `scripts/loading-recovery-check.js`: exercise suspended animation frames, first
  canvas rendering under the loading overlay, and an image refresh during zoom.
- `scripts/hatch-spatial-check.js`: compare independent full-source hatch paths
  pixel-for-pixel at three scales and verify original entity picking.
- Rejected and removed image cropping/resolution caches, density-based hatch fills,
  altered easing and full-hatch raster caches. None met the high-DPI acceptance
  boundary. There is no texture simplification or new cache in the final source.
- Preserved the updater, sidecar cold-open optimization, fixtures, other uncommitted
  files and the original viewer-check deadlines. No commit or release was made.
