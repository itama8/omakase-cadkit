# 2026-10-25 / s04 — Public library entry and a separate consumer

Outcome: O3 done (Linux x64, source checkout) · State: done
Source: `673837c` · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426, Node 24 in CI

## Result

Another package can open a drawing, filter entities, lint, render SVG, and stop the
sidecar through one documented entry point, without importing `src/cli.ts`,
`src/server.ts`, or `viewer/`. A package outside the repository does exactly that
in CI with only `omakase-cadkit` as a dependency.

## Changes and decisions

- [src/index.ts](../src/index.ts) is the public entry: `Cadkit`, `CadkitError`,
  `DrawingHandle`, and the payload/config/lint/sheet/SVG types. `package.json`
  gained `exports` and `types` pointing at it, so consumers import the package
  name rather than a deep path.
- The surface was chosen from real CLI calls, not from what the internals expose:
  `open` (store + config), `entities`/`entity`/`layerName` (the `query` command),
  `lint` (the `lint` command), `render` (the `render` command), `close`.
  `Cadkit` starts nothing until the first uncached `open`, and `DrawingHandle`
  methods are synchronous because the payload is already parsed.
- [src/query.ts](../src/query.ts) now holds the filter matcher, and
  `src/cli.ts` builds a filter and calls it. Before this, the CLI had the only
  copy; a library reimplementation would have drifted. The matcher is compiled
  once per query, and it resets `lastIndex` so a caller-supplied `/g` expression
  does not skip matches.
- Ownership is explicit rather than implied: `Cadkit.running` reports whether a
  sidecar is alive, `Cadkit.closed` whether the instance still accepts opens, and
  `close()` is idempotent. Drawings already returned keep working after `close`
  because they own parsed data, not a process. Opens after close throw
  `CadkitError` instead of silently respawning a worker.
- Errors: `open` surfaces the store's messages (missing file, wrong extension,
  unbuilt or crashed sidecar, timeout, schema). An unknown render handle throws
  `CadkitError`; a missing bbox throws with the fix (`pass render({ bbox })`).
  A broken rule still lands in `LintResult.ruleErrors`, not an exception.
- [examples/library-consumer/](../examples/library-consumer/consumer.ts) is a
  separate package with `"omakase-cadkit": "file:../.."`, its own `tsconfig.json`,
  and a script that installs it, typechecks it, and runs it. `npm run consumer`
  drives it, and CI runs that command as its own step.
- The package still publishes TypeScript sources (`exports` → `src/index.ts`), so
  consumers need Node's type stripping. A compiled JS/`.d.ts` distribution is
  O4, not something to fake here.
- The first version of [test/library.test.ts](../test/library.test.ts) asserted
  that any `open` starts a sidecar and failed on a warm payload cache. It now
  opens a fresh copy of the fixture, which makes the spawn deterministic and
  documents that a cached open does not start a process.
