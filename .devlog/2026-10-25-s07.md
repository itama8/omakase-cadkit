# 2026-10-25 / s07 — Opening your own drawing just works from a terminal

Outcome: O1 · State: done (Linux x64; usability fix)
Source: this change · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426

## Result

The first real attempt to open a project DWG failed: `omakase-cadkit inspect '~/<project folder>/<sheet>
& <sheet>.dwg'` reported `no file at <checkout>/~/…`. The path has spaces and `&`, so
it has to be quoted, and a shell does not expand `~` inside quotes. The CLI and the viewer
server now expand a leading `~` themselves. `view` also opens the browser, replaces a viewer
server left over from an older build, and rejects a missing or non-drawing file in the terminal.

## Changes and decisions

- `expandHome` in [store.ts](../src/store.ts) is applied to CLI positional arguments and flag
  values, in `DrawingStore.resolve` (so the library gets it too), and to the server's `file` and
  `dir` parameters, so a `~` path typed in the viewer's path box also works for lint and profile
  lookup. Only `~` and `~/` expand; `~user` is left alone.
- `view` opens the URL with `xdg-open`/`open`/`start` when stdout is a TTY. Agents and scripts
  that pipe stdout get only the URL. `--open` and `--no-open` override.
- `/api/health` reports `app`, `build`, and `pid`. `build` is the newest mtime among the
  package's modules and the sidecar DLL ([sidecar.ts](../src/sidecar.ts) `buildStamp`). `view`
  sends SIGTERM to a server whose build differs and starts a fresh one. This removes the trap of a
  detached server quietly running pre-rebuild code. A server from before this change reports no
  build or pid; `view` warns and names the `pkill` command instead of guessing which process to
  kill.
- `view` validates through `DrawingStore.resolve`, so `view ~/.bashrc` fails with "not a .dwg or
  .dxf file" instead of printing a URL that errors in the browser.
