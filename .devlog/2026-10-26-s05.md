# 2026-10-26 / s05 — Setup and Launch green on four platform/arch runs

Outcome: O9 · State: done (Linux x64, macOS arm64/x64, Windows x64)
Source: `2dafce4` plus this change · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426; CI Ubuntu 24.04, macOS 14, macOS 15 Intel, Windows Server 2022

## Result

The Windows Setup run no longer crashes, so a tester on Linux x64, macOS (Apple
Silicon or Intel) or Windows x64 can download the ZIP, run Setup once and launch
the app. CI proves that path on each of those platforms: it downloads private
tools, runs Setup, then opens `sewer_bad.dxf` through Launch and reads health,
drawing and lint over HTTP.

The Windows failure from run 40220957945 was a real defect, not a flaky runner:

```
Error: IOException: The process cannot access the file
'C:\Users\runneradmin\.cache\omakase-cadkit\52068c6abdc6e8037120.json.tmp'
because it is being used by another process.
```

`test/library.test.ts` and `test/omakase-cadkit.test.ts` both open
`fixtures/sewer_clean.dxf`; `node --test test/*.test.ts` runs them as separate
processes against one cache directory. Both sidecars wrote the same
`<hash>.json.tmp`, and Windows refuses a second `File.Create` on an open path,
where POSIX lets both writers reuse it. The same collision can happen to a person
with two viewers open on one drawing, so it is fixed in the writer rather than in
the tests.

Alpha distribution is still a source ZIP. There is no npm package: `package.json`
is private, `dist/` is not committed, and the sidecar travels as C# source. That
is O4, and the sidecar shipping choice is still open.

## Changes and decisions

- `sidecar/Program.cs`: `Open` and `Convert` write a unique sibling temp file
  (`TempFor`, a GUID suffix), move it over the output, and delete it on failure
  (`TryDelete`). Concurrent writers can no longer share or leak a temp path.
- `setup.cmd`, `launch.cmd`: the failure `pause` now requires an interactive
  console. A scripted or CI run exits with the code instead of waiting for a key.
  This also removes a way for the Windows CI step to hang until its timeout.
- `.github/workflows/ci.yml`: added `macos-15-intel` to the bootstrap matrix, so
  both Mac architectures are covered, and a drawing-open step per OS that calls
  the real launcher (`launch.command` / `launch.cmd`), then checks
  `/api/health`, `/api/drawing` and `/api/lint` with `curl --compressed`. A green
  Setup no longer stands in for the app working.
- `sidecar/Program.cs`: dropped the `?` nullable annotations from `TextPlain`,
  `IsSerif` and `FaceWidth`. The project sets `<Nullable>disable</Nullable>`, so
  they were only CS8632 warnings, and s04's push made CI annotated.
- `README.md`, `docs/setup.md`: platform claims now name the four CI runs and
  their limits, and a new "Trying an alpha" section states that an alpha is a
  source ZIP, which limits are known, and what a useful report contains.
- `docs/outcomes.md`: O9 done with the CI evidence; O1 and O10 rows now link the
  platform coverage and the s04 text work.
