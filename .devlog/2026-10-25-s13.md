# 2026-10-25 / s13 — Setup installs missing tools and remembers them for Launch

Outcome: O9 · State: partial (Linux x64 verified; Windows/macOS pending)
Source: this change · Environment: Linux x64, system Node 25.8; fresh downloaded Node 24.22.1, .NET SDK 8.0.426, uv 0.13.4

## Result

A source ZIP/checkout now has platform Setup and Launch entry points. Setup checks tools,
installs missing dependencies beside the app, builds and verifies it, and remembers the
paths. Launch opens the empty browser viewer without requiring tools on the caller's PATH.
Windows and macOS scripts exist, but only Linux x64 was exercised on a real host here.

## Changes and decisions

- `setup.command`, `setup.cmd`, `scripts/bootstrap.ps1`: bootstrap Node before running
  shared JavaScript. Downloads use the official Node 24 LTS archives and SHA-256 manifest.
  Windows has PowerShell and ZIP extraction; macOS/Linux use Bash, curl and tar.
- `scripts/bootstrap.mjs`: reuse suitable Node/.NET/uv; otherwise install the .NET 8 SDK
  and runtime with Microsoft's installer and uv 0.13.4 with Astral's installer under
  `.tools/`. Installer shell-profile modifications are disabled. No admin escalation,
  global npm link, persistent PATH modification, or system package-manager changes.
- `--check` / `-Check` reports dependencies without installing. `--local-tools` /
  `-LocalTools` ignores system tools for reproducible downloads/CI. Node 24 is the
  bootstrap baseline; the manual source minimum remains Node 23.6.
- Setup runs `npm ci`, then the existing `npm run setup`. Only after all checks pass
  does it write `.tools/environment.json` and the Node path used by the Unix launcher.
  A failed setup is rerunnable; successful reruns reuse private tools.
- `launch.command`, `launch.cmd`, `scripts/launch.ps1`, `scripts/launch.mjs`: launch with
  the saved Node and .NET paths, explicitly opening the browser even without a TTY.
  `--no-open` remains available for scripts and CI. PowerShell reads saved paths on
  Windows; no shell-string interpolation of saved tool paths is needed.
- `src/sidecar.ts`: recognize Windows `.exe` names; DLL fallback tries dotnet on PATH
  if the per-user location does not exist. `src/server.ts`: use `fileURLToPath` for
  direct-entry detection. The prior URL/string comparison failed in folders with spaces
  and on Windows. Fixed the properties test cleanup so an already-exited child cannot
  hang its failure path.
- `.github/workflows/ci.yml`: new Linux/macOS/Windows bootstrap matrix installs private
  dependencies and launches the empty app. These jobs have not been pushed/run here.
- `.tools/` is ignored. Existing concurrent hatch/schema/rendering work was preserved.
  The test copy included that in-progress work, hence 24 tests rather than the earlier 23.
