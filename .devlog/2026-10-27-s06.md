# 2026-10-27 / s06 — Recover large-drawing interaction and cold-open performance

Outcome: O6 · State: active
Source: this change · Environment: Linux x64, Node 25.8.0, .NET 8, T3 Chromium preview and headless Chromium at 1500×900 DPR 1

## Result

The renderer changes and relaxed viewer-check deadlines below were rolled back
after the user reported a zoom regression; see [s07](2026-10-27-s07.md). The
sidecar cold-open improvement remains.

Reproduced the reported slowness on the two most recent Silchar drawings (141,361
and 152,702 primitives). Selection discarded all raster tiles, including the aerial
image. One selection took 385 ms. Moving selection into an overlay reduced that
same operation to about 0.2 ms without rendering a tile. Scheduled pans now obey
the tile rendering budget even when no previous zoom layer exists.

Cold opening the larger drawing took 20.7 s to become displayable, mostly hatch
conversion. Continuous hatch conversion now retains ACadSharp's intersection and
parity calculations but caches straight boundary geometry, rejects edges clearly
on one side of the line, and emits coordinate tuples instead of temporary CAD
entities. The complete 75,137,093-byte payload is byte-for-byte identical to the
original. First-open display fell to 6.37 s; returning to it after another drawing
was displayable in 236 ms (checks complete in 326 ms).

This is improved, not instant everywhere: the heavier drawing's detail-pan p95
was 32.9 ms, max 45.6 ms in software Chromium. Native desktop/GPU and installed
Windows/macOS builds remain unverified.

## Changes and decisions

- `viewer/canvas.ts`: selection no longer invalidates base tiles. Geometry, text,
  fills and tiny-selection markers draw in an overlay using the same text layout.
  Every scheduled frame budgets new tiles, including a pan and the initial fill.
  Direct `draw()` still completes synchronously for export/check callers.
- `sidecar/Patterns.cs`, `sidecar/Program.cs`: optimize continuous hatch families;
  dashed families retain their prior expansion. Keep the drawing-wide segment
  budget and payload schema unchanged. Attribution is in the source and
  `THIRD_PARTY_NOTICES.md`. A different polygon clipper was rejected because it
  changed the payload; it is not included.
- `fixtures/make_fixtures.py`, `test/hatch.test.ts`: add surveyed-coordinate nested
  islands with horizontal/vertical families and both edge/polyline encodings.
  Assert row lengths, offsets, parity and total segment length.
- `scripts/viewer-check.js`: pixel checks for selected line/text, tile reuse and
  clearing selection. Progressive zoom completion waits for actual settled state
  with a 3 s failure deadline; the prior fixed 460 ms wait failed on the larger
  drawing. Pan frame benchmarks remain independent of this functional deadline.
- The process on port 4280 was from this checkout but ran an older backend against
  newer viewer assets (`/api/update` returned 404). Rebuilt and restarted through
  the CLI. Existing updater work and all unrelated edits were preserved.
