# 2026-10-27 / s03 — Windows installer, windowless worker, open button

Outcome: O11 · State: verifying (Windows CI and tester retest pending)
Source: this change · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426, headless Chromium

## Result

The Windows tester's report, restated: after double-clicking `launch.cmd` from the
alpha.1 ZIP, a terminal window opened each time a file was selected, and each open
took over 15 seconds. The drawing itself then rendered correctly.

Probable cause (reasoned from the code, not observed on Windows): alpha.1 started the
viewer server detached with no console, and spawned the console-subsystem sidecar
without `windowsHide`, so Windows gave the sidecar its own visible console. Closing
that window kills the sidecar. The next open then cold-starts a compressed,
JIT-only, self-contained single-file executable again, behind a new window. On Linux,
the same 4.9 MB trial DWG takes 1.4 s end to end, cold sidecar included, and 75 ms
on repeat, so conversion work does not explain 15 s.

Changes:
- The sidecar publishes with ReadyToRun and without single-file compression. On
  Windows RIDs it is a `WinExe`, so it cannot create a console even if a spawn
  forgets `windowsHide`. The server starts it with a `ping` at listen time.
- `omakase-cadkit.exe` (`launcher/`, .NET Framework 4.8, 8.7 KB) runs the bundled
  Node on `scripts/launch.mjs` with no console window and reports failures in a
  message box. It ships in the Windows ZIP.
- `installer/omakase-cadkit.iss` (Inno Setup 6) builds a per-user installer:
  `%LOCALAPPDATA%\Programs`, Start menu entry, optional desktop icon, **Open with**
  for .dwg/.dxf (OpenWithProgids, AutoCAD's default is untouched), and an
  uninstaller. Installing or uninstalling runs the new `omakase-cadkit stop` first.
- The empty screen's drawing illustration is now a button. It opens the system
  "open file" dialog for DWG/DXF and loads the choice; cancelling changes nothing.

## Changes and decisions

- `sidecar/OmakaseCadkitSidecar.csproj`: conditional `WinExe` for `win-*` RIDs.
  Dev builds without a RID stay console `Exe`. Run from a terminal, the Windows
  bundle sidecar no longer prints to that terminal; only Node uses it.
- `scripts/bundle.mjs`: ReadyToRun publish; on Windows build the launcher into the
  folder and the installer via ISCC. In CI a missing ISCC fails the build; locally
  it warns and keeps the ZIP. The new START-HERE recommends `omakase-cadkit.exe`.
- `src/server.ts`: sidecar warm-up on listen; `/api/pick-drawing` shares the
  folder picker's POST, same-origin and single-picker guards.
- `src/file-picker.ts`: `pickDrawing`: Windows OpenFileDialog, macOS `choose file`
  of type dwg/dxf, Zenity with KDialog fallback.
- `src/cli.ts`: `stop [--port]` ends a running viewer server, and its sidecar
  with it. Exit 0 when nothing is running.
- The launcher waits for process exit, not end of output. The detached server can
  inherit the output pipes, so EOF may never arrive.
- `.github/workflows/ci.yml`: ensures Inno Setup on Windows. Silently installs per
  user, runs `check-bundle.mjs` against the installed folder (through
  `omakase-cadkit.exe`), then uninstalls and checks the files are gone. The setup
  exe is uploaded and attached to `v*` releases.
- Decision (user, 2026-10-27): ship the installer and launcher unsigned. SmartScreen
  shows "Windows protected your PC" → More info → Run anyway; the docs say so.
  Revisit signing (e.g. Azure Trusted Signing) only if testers are blocked by it.
- App icon (user request): Omakase's 任 tile from `../omakase-v2/build/icon-source.svg`,
  recoloured black and dim blue (`#6f8fc2` linework instead of gold), with drafting marks: grid, CENTER-linetype construction lines, ANSI31 hatch inside a
  crisp glyph outline, architectural dimensions in font units (944 × 926), blue
  AutoCAD-style grips on outline vertices, and a crosshair with pickbox. 16–64 px use
  a simplified solid glyph with one grip so it stays legible. `scripts/make-icon.mjs`
  embeds the glyph outline (Noto Sans JP Medium, OFL; notice and license added) and
  writes `assets/` (SVGs, 1024 PNG, multi-size .ico) and `viewer/favicon.svg`; it needs
  rsvg-convert and magick, the outputs are committed. The .ico is the launcher's
  ApplicationIcon (exe now 381 KB), the installer's SetupIconFile and the Open-with
  DefaultIcon; the favicon also replaces the viewer header's brand mark.
- Package version stays `0.1.0-alpha.1`; no tag or release was made.
