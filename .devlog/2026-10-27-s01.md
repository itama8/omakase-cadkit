# 2026-10-27 / s01 — Browse Windows drives and make drawing opens visible

Outcome: O11 · State: verifying (Windows desktop acceptance)
Source: this change · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426, headless Chromium

## Result

The initial navigation described here was superseded by [s02](2026-10-27-s02.md);
its load/cache changes remain in the final implementation.

A Windows tester of the published alpha reported difficulty finding a drawing on
another drive, a console window on file opens, and loads exceeding 15 seconds.
The ZIP correctly contains Launch without Setup: it already includes its runtimes.
That distinction is now explicit in download instructions and generated START-HERE.

The source viewer now has Browse, a Windows system drawing picker, and Computer
for selecting existing drives without guessing letters. Windows backslashes and
files at drive roots retain their proper folder and display name. Initial browsing
uses the most recent existing drawing's folder. Worker spawns request hidden
Windows consoles. These Windows desktop behaviors need a tester retest; Linux
checks cannot prove their native appearance.

Repeated opens retain up to three parsed browser payloads. The server validates
file identity before returning 304, avoiding repeat compression, transfer and JSON
parsing when the drawing is unchanged. Changed size/mtime or sidecar build forces
a fresh response. Loading shows the filename, phase and elapsed seconds; the
status bar keeps completion timing, with server read/emission/parse measurements
for a first conversion and browser payload/display/check durations on hover.
This does not establish the cause or resolution of the tester's 15-second loads.

## Changes and decisions

- `src/file-picker.ts`: Windows Forms OpenFileDialog through built-in PowerShell
  in STA mode, hidden console, drawing extension filter, Unicode output, paths
  passed through an environment variable. No additional runtime is installed.
- `src/server.ts`: same-origin POST for a single active native picker; Computer
  root listing and last-folder default; ETag revalidation and Server-Timing.
- `src/sidecar.ts` and `src/cli.ts`: hide child console windows on Windows.
  The existing sidecar remains persistent across drawing opens.
- `viewer/main.ts`: Windows path handling, Browse/Computer actions, bounded
  payload reuse, abort superseded browser transfers, elapsed feedback and timings.
  Initial DWG conversion and rebuilding canvas indexes can still cost time.
- `test/opening.test.ts` covers real HTTP revalidation, changed-file invalidation,
  filesystem roots, recent-folder default, and picker request method/origin checks.
- `scripts/opening-check.js` adds repeatable browser checks; its Windows path cases
  substitute source-path metadata, not a Windows filesystem or native dialog.
- No tag, release, commit, or published ZIP was changed. The local bundle still
  uses package version alpha.1 and is development evidence, not a new release.
