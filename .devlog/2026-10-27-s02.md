# 2026-10-27 / s02 — Choose a folder and simplify navigation

Outcome: O11 · State: verifying (Windows desktop acceptance)
Source: this change, following s01 · Environment: Linux x64, Node 25.8.0, headless Chromium, Zenity/desktop portal

## Result

The user rejected the Computer button, editable path and Go flow introduced in
s01. Folder icons in Files and the header now open a system **folder** picker.
Choosing a folder changes the file list; selecting a drawing remains a separate
click in that list. The current folder is a read-only name with its full path on
hover. A thin, curved left arrow in the former Go position returns to the parent;
it is disabled at a filesystem root. The ambiguous `..` list item is removed.
Both side panels now collapse with crosses and reopen through their existing
edge tabs.

## Changes and decisions

- `src/file-picker.ts`: Windows FolderBrowserDialog, macOS choose-folder dialog,
  Linux Zenity with KDialog fallback. Paths remain data rather than script text.
  Linux needs one of those desktop dialog programs; neither is bundled. Windows
  and macOS use system components. Cancel leaves the current folder unchanged.
- `src/server.ts`: same-origin POST `/api/pick-folder`, one active picker, and
  filesystem parents that remain at their root. Removed the Computer API branch.
- `viewer/main.ts`, `viewer/index.html`, `viewer/style.css`: read-only folder row,
  curved parent arrow, native folder selection on all three OS families, cross
  icons for panel collapse. Removed path editing, Go and Computer controls.
  The final Browse control is an icon with a tooltip and accessible label.
- Updated README, source/next-download instructions, bundle START-HERE text,
  outcome map and the existing opening interaction checks to match this flow.
- The tester's files were 3–5 MB, with the largest seen around 8 MB. They did not
  reopen drawings. The complaint therefore concerns first opens; repeat caching
  does not establish its resolution. No new latency claim is made here.
