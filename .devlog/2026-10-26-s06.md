# 2026-10-26 / s06 — A downloadable alpha ZIP that works from a spaced folder

Outcome: O1, O9 · State: done (Linux x64, macOS arm64/x64, Windows x64)
Source: `d7a1dca` plus this change · Environment: Linux x64, Node 25.8.0; the rehearsal used the downloaded Node 24 and .NET 8 SDK in `.tools/`

## Result

The artifact a tester downloads now passes the whole path on this machine: ZIP
extract, `setup.command` with private tools, and `launch.command` opening a
drawing whose lint returns 8 findings across 8 rules. The folder path contained a
space (`/tmp/alpha rehearsal/omakase-cadkit`), which is the case that used to
break launched folders on Windows and in the viewer entry.

`git archive HEAD` was used as the stand-in for GitHub's "Download ZIP"; the two
differ only in GitHub's compression, not contents. Executable bits survived for
`setup.command` and `launch.command` (755, LF), and the batch files are CRLF as a
Windows user expects.

Distribution is still a source ZIP. O4 (an installable package) stays active, and
the sidecar shipping choice remains open, so testers need no tools but do need
internet and several hundred MB on first Setup.

## Changes and decisions

- `.gitattributes`: `*.cmd` checks out and archives as CRLF, `*.command` stays LF.
  The batch files are short enough that cmd.exe accepted LF, but ZIP contents
  should look like Windows files, and bash refuses a CRLF script.
- `package.json`, `package-lock.json`: version `0.1.0-alpha.1`. Nothing reads it
  yet (there is no `--version`); it labels the snapshot and the tag. `private`
  stays true because publishing is still disabled.
- `docs/outcomes.md`: O1 now records the platform spread and keeps the SVG and
  Chromium checks scoped to Linux; O9 already carries the CI evidence.
