## Changes and decisions

- [CI workflow](../.github/workflows/ci.yml) runs on `ubuntu-24.04` and Node 24:
  `npm ci`, `npm run setup`, then `npm run smoke`. It repeats the contributor
  path rather than a private one, and deliberately does not publish npm packages
  because `private: true` still stands.
- Added `scripts/smoke.mjs` (`npm run smoke`) to [package.json](../package.json)
  so CI exercises the shipped entry points, not just unit tests: `inspect`,
  `lint` on the clean and bad fixtures with their expected exit codes, `render`,
  and the viewer server's health, asset, drawing, and lint endpoints. It runs
  against a temporary `OMAKASE_CADKIT_CACHE` and never needs Chromium, so CI has
  no browser dependency.
- Pinned every action to a full commit SHA with its tag in a comment, and gave
  each job `permissions: contents: read` plus a `concurrency` group.
- **Fixed two defects that would have failed the first CI run:**
  - The `astral-sh/setup-uv` pin resolved to no commit in that repository
    (`422` from the API). Replaced with the verified `v7.6.0` SHA
    `37802adc94f370d6bfd71619e3f0bf239e1f3b78`.
  - `OMAKASE_CADKIT_CACHE: ${{ runner.temp }}/...` sat in job-level `env`, where
    the `runner` context is unavailable. `actionlint` rejected it; the variable
    now lives on the two steps that need it.
- `package.json` gained `license`, `repository`, `bugs`, and `homepage` pointing
  at `itama8/omakase-cadkit`, the account and name checked as available. The
  lockfile was regenerated with `npm install --package-lock-only`.
- The public tree no longer contains the client project name. README, setup
  docs, the test comment, and the s01 devlog now say "private drawing", and the
  opt-in variable is `OMAKASE_CADKIT_PRIVATE_DWG`. Two reasons: the test had
  drifted back to the old client-named variable, contradicting the s01 record,
  and [CONTRIBUTING](../CONTRIBUTING.md) already asks that exported client
  content stay out of commits.
- Open choice for the next person: the history then still held the private
  drawing's absolute path in a removed line. Nothing was published, so it could
  be rewritten before the first push. Resolved in
  [s03](2026-10-25-s03.md): the commits were rewritten and the affected log text
  summarized, so no reachable commit now names the drawing or its path.
