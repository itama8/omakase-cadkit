# 2026-10-26 / s07 — Testers download one ZIP and launch it

Outcome: new O11 · State: done (Linux x64, macOS arm64/x64, Windows x64)
Source: `5c6daee` plus this change · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426; CI on Ubuntu 24.04, macOS 14, macOS 15 Intel, Windows 2022

## Result

The tester route was: download a source ZIP, run a Setup script that fetched a
Node/.NET/uv toolchain, built the app and ran 27 tests, then launch. That is now:
download one ZIP (64–75 MB), unzip, double-click. The archive contains a
self-contained sidecar, so the machine needs no .NET at all, plus the Node runtime
that runs the compiled CLI and viewer.

Each of the four archives is built on its own CI runner and then **launched there
with no Node or .NET on `PATH`**, required to answer health and to return a lint
finding. A Linux archive was also run by hand from a folder whose path contains a
space. The old source-ZIP route still exists for contributors and for platforms
without an archive (Linux ARM64, Windows ARM64).

The sidecar ships as a 36 MB single-file self-contained binary; the Node runtime is
the one Setup downloads, so the bundle inherits the Node 24 that CI already tests.
Nothing is published to npm: `package.json` is still private, so O4 is untouched.

## Changes and decisions

- [scripts/bundle.mjs](../scripts/bundle.mjs): builds `dist/`, the viewer bundle and
  a `dotnet publish -r <rid> --self-contained -p:PublishSingleFile=true` sidecar,
  copies the Node binary and the launcher, writes `.tools/node-path.txt` and
  `.tools/environment.json` with **relative** paths so the folder can be moved, adds
  `START-HERE.txt`, and zips (PowerShell `Compress-Archive` on Windows, `zip`
  elsewhere).
- [scripts/check-bundle.mjs](../scripts/check-bundle.mjs): launches the built bundle
  with `PATH=/usr/bin:/bin` and `HOME` in a temp dir (Windows keeps its system
  directories but replaces `HOME`), waits for `/api/health`, requires a
  `sewer-levels` finding from `/api/lint`, then stops the server it started. CI runs
  it on all four platforms, so "built" is never mistaken for "works".
- `.github/workflows/ci.yml`: bundle build + launch + `upload-artifact` in the
  bootstrap matrix; a `release-assets` job on `v*` tags downloads the four ZIPs and
  uploads them to that tag's release, creating a draft if none exists. Artifact
  actions are v7/v8 (node24), because v5 still declared node20 and added a
  deprecation annotation.
- Launchers: `scripts/launch.ps1` resolves a relative saved Node against the app root
  (a bundle saves relative paths), and `launch.command` no longer exits silently when
  `node-path.txt` has no trailing newline — `read` returns 1 there and `set -e`
  killed the script. The bundle's paths exercise both.
- Setup flake: a Windows CI job failed with `Access to the path
  '.tools\node-download-…\unpacked\node-v24.22.1-win-x64' is denied`. Setup ran
  `node.exe` from inside that directory and then moved it; an antivirus scan kept the
  directory open. `scripts/bootstrap.ps1` now extracts with `tar.exe` (no lingering
  handles, unlike `Expand-Archive`), moves first with five retries, and verifies Node
  from its final path. `setup.command` got the same order. The bundle route was never
  affected, but contributors on Windows and CI signal were.
- `docs/setup.md` is now "# Install" with **Install a download** first and **Set up a
  source checkout** second; README leads with the download; AGENTS.md documents
  `npm run bundle`. `docs/outcomes.md` gains O11.
