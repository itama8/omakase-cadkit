## Result

The reported boxed label now has an uninterrupted filled border on all four sides
and a hollow interior. This corrects s12, whose text-box subtraction cut through the
top and bottom edges. The original screenshot check accepted that defect, and its
pixel test incorrectly asserted that the border should be cut. Those assertions
have been replaced with checks along the full top and bottom edges.

## Changes and decisions

- Filter `Textbox`/`TextIsland` boundary paths out of hatch fill geometry in the
  sidecar. Keep the actual geometric loops, including nested holes. This follows
  the approach of ezdxf's drawing frontend, which calls `ignore_text_boxes` before
  drawing filled paths: [primary source](https://github.com/mozman/ezdxf/blob/master/src/ezdxf/addons/drawing/frontend.py).
- Remove the extra exclusion-loop payload, canvas clipping and SVG masks from s12.
  Schema 5 invalidates schema-4 cached output. Rebuilt the sidecar, library and
  viewer; removed drawing payload JSON while preserving recent files/preferences;
  restarted only the main viewer server on port 4280. Unrelated work was preserved.
- Independent geometric fills still render separately so their parity holes cannot
  cancel neighboring hatches. Selection also uses the actual geometric fill.
- Updated `test/hatch.test.ts` and `scripts/hatch-check.js` to require continuous
  frame edges despite overlapping text-box metadata extending beyond those edges.
  Tests still cover nested holes, underlying linework, overlapping independent fills,
  and a transformed block. Text-box metadata no longer punches holes into a solid
  geometric fill. Dedicated text background-mask support is not implemented here;
  CAD fonts and broader hatch-style fidelity remain separate work.
