# Devlogs

A devlog records one meaningful change: what changed, why, how it was checked, and
what the next person should do.

- Name it `YYYY-MM-DD-sNN.md` with an unused number, and copy
  [TEMPLATE.md](TEMPLATE.md).
- Keep it short. Leave out empty sections.
- Give exact commands and their real results. Say what was not checked.
- Link evidence others can open (files in the repo, CI runs). Never include private
  drawing content, credentials or personal paths.
- Write "this change" instead of guessing a commit hash.
- Old devlogs are history. If a conclusion changes, write a new entry instead of
  editing the old one.

Current direction lives in [the outcome map](../docs/outcomes.md), not here.
