# 2026-10-25 / s05 — Installable package rehearsal, without a sidecar strategy

Outcome: O4 active (compiled output and tarball install work; sidecar distribution undecided)
Source: `5dfae84` plus this change · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426

## Result

`npm pack` now produces a 130 kB tarball whose installed CLI and library work outside
the checkout for everything that does not need the sidecar. An installed `inspect`
still fails because the package ships the sidecar's source, not a runnable binary.
Choosing how the sidecar travels is the remaining decision, so the outcome stays
active.

## Changes and decisions

- The first rehearsal proved the failure mode: installing the tarball and running the
  CLI died with `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`, because `bin/` imported
  `src/cli.ts` and its `.ts` imports. Node refuses to strip types inside
  `node_modules`. The package also had no `exports`, no `dist/`, and no viewer bundle.
- [tsconfig.build.json](../tsconfig.build.json) emits `dist/` JavaScript, declarations,
  and source maps with `rewriteRelativeImportExtensions`, so the `.ts` specifiers in
  the sources become `.js` in the output. `npm run build:lib` runs it; `npm run build`
  and `npm run setup` include it.
- `bin/omakase-cadkit.mjs` now loads `dist/cli.js` and prints a build instruction when
  it is missing, instead of an obscure module error. `package.json` gained
  `exports`/`types` pointing at `dist/`, plus a `files` allowlist.
- `src/cli.ts` chose its viewer-server entry as a hard-coded `server.ts`. That string is
  not rewritten by tsc, so `view` would have broken from `dist/`; it now picks
  `server.js` or `server.ts`, whichever exists.
- **A near miss:** the first `files` allowlist named `sidecar/` and `bin/sidecar/`. A
  `files` entry overrides `.gitignore`, so the tarball grew to 1.3 MB and included
  `sidecar/obj/`, `sidecar/bin/`, a locally built Linux binary, and NuGet files that
  contain this machine's absolute paths. The list now names only
  `sidecar/Program.cs` and `sidecar/OmakaseCadkitSidecar.csproj`; the tarball is 65
  files with no build output.
- `docs/setup.md`, `AGENTS.md`, and the README now say that tests and tooling run the
  sources while the shipped CLI and library run `dist/`.
- Open choice, and the reason O4 is not done: **how the sidecar travels**. Options
  considered: per-platform optional dependencies that carry a self-contained binary (no
  .NET on the user's machine, large packages, per-platform CI builds); framework-dependent
  binaries plus a documented .NET 8 runtime prerequisite (small, but an install step many
  users will not have); or building from the included source on install (needs the .NET
  SDK, so it defeats the point). This changes package layout, CI, and supported-platform
  claims, so it needs a decision rather than a unilateral default.
