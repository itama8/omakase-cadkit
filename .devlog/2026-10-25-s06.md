# 2026-10-25 / s06 — Linked raster underlays render, including inside blocks

Outcome: O5 · State: later (fidelity increment; outcome map unchanged)
Source: this change · Environment: Linux x64, Node 25.8.0, .NET SDK 8.0.426

## Result

A drawing with an `IMAGE` backdrop now shows the referenced raster in the viewer, under the vector
geometry and at the same world transform, including rectangular clipping. `render` embeds small
rasters in SVG; large ones are named in the SVG and left out. Images inside blocks are drawn at
each insert's transform. Images meant to sit above vector geometry are still drawn beneath it.

## Changes and decisions

- Sidecar payload schema 2: an `IMAGE` entity now carries `ins`, pixel `size`, per-pixel `u`/`v`
  world vectors, `show`, `fade`, and the clip boundary. `src/types.ts` and
  `sidecar/Program.cs` were bumped together.
- Schema 3: the sidecar also writes `rasters`, one world-space record per drawn image (`ent`, image
  handle `h`, resolved layer, `file`, `ins`, `u`, `v`, `size`, `fade`, `clip`), collected while
  emitting primitives, so images in blocks (nested to any depth) get the composed insert transform
  and layer-0 content takes the insert's layer. The viewer, SVG export, and `/api/raster` read
  this list instead of top-level `IMAGE` entities. The viewer fetches each image handle once even
  when a block places it many times. SVG clip ids are per placement (`raster-<index>`).
- [store.ts](../../src/store.ts) regenerates a cached payload when it is unreadable or carries an
  older schema. The cache key is path/size/mtime, so without this a pre-change payload would
  keep the new fields out of the viewer forever.
- `/api/raster` in [server.ts](../../src/server.ts) resolves the drawing's image reference against
  the drawing directory (with a base-name fallback), accepts only common browser image types, caps
  the file at 64 MB, and streams it. The browser never supplies the path: it supplies a drawing and
  an entity handle, and the server uses the payload's `file`.
- [canvas.ts](../../viewer/canvas.ts) draws each loaded bitmap into every raster tile before the
  vector batches, using the existing view transform. Layer visibility, fade, and clipping apply.
  A two-vertex DXF boundary is treated as a rectangle.
- SVG export embeds rasters as data URIs only when the file is present and at most 6 MB. A 16 MB
  backdrop produced a 33 MB SVG that `rsvg-convert` rejected (`XML_PARSE_HUGE` text-node limit);
  the cap keeps the PNG export path usable. Skipped files are listed in an SVG `<desc>`.
- `raster_underlay.dxf` also holds block `RASTER_STAMP`, which contains the same image and is
  inserted plainly at (100, 20) and rotated 90° at 2× scale at (150, 20).
- New fixture `raster_underlay.dxf` and generated `raster.png`; tests assert the payload transform,
  clip window, and SVG embedding. `fixtures/*.png` is ignored like the generated DXFs.
